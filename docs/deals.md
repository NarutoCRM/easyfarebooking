not verified promotions. The system does not display fabricated prices,

## Data and templates

`data/deals.ts` is the editorial source. A category object contains its ID,
canonical path, optional redirect alias, visual tone, title, summary, original
introduction, overview, intended audience, considerations, five FAQs, route IDs,
related category IDs, search defaults and SEO fields.

A route object contains its unique slug, origin/destination cities and actual
IATA codes, domestic/international classification, original introduction and
specific planning notes. The normalized object supplies its canonical path,
title, description and five route-relevant FAQs.

Add a category or route object to extend the system. Attach a route ID to at least
one category so it has an inbound link. New nested categories are generated by
`app/deals/[slug]/page.tsx`; directed route guides use
`app/deals/routes/[slug]/page.tsx`. Unknown slugs return 404. Adding another root
canonical category requires a small compatibility wrapper like the existing five.

`DealPage` handles both kinds of detail guide. `DealCard` provides distinct visual
tones for U.S., international, urgent, premium, trip-structure and family planning.
`RouteDealCard`, `DealSearch`, `FlightPlanningTips` and `DealCTA` are reused by the
directory and detail pages. The global header, footer, branding and CSS are
unchanged.

The five large duplicated `site-pages/*FlightDeals.tsx` implementations were
replaced with small wrappers around `DealPage`. Their route files and import
locations were retained. Existing planning concepts and all distinct city pairs
were incorporated; inaccurate online-booking instructions were replaced with
honest demo-search and contact-assistance copy. The incomplete `FlightDeals`
component, including its missing type references, was replaced with a working
directory collection.

## Search integration

The existing `BookingWidget`, airport normalization, validation, loading behavior
and `/flights/search` routing are reused. Route pages prefill complete airport
records on the server and retain the autocomplete and swap controls.

`defaultTripType` sets One Way or Round Trip on the corresponding category.
`defaultCabin` supplies a premium-cabin starting point only when no saved choice
exists. `initialValues`, including the results page's Modify Search values, take
precedence over defaults and session restoration.

Dates, return date, traveller count, cabin and trip type are stored only in
`sessionStorage` under `easyfarebooking:flight-search:v1`. On navigation or refresh
within the same browser session, valid saved values are restored. Airport pairs
follow the guide's context, and an explicit one-way or round-trip category
controls its trip type without clearing the other saved fields. Draft parsing
rejects malformed values; search still works when storage is unavailable. This
is browser-session convenience, not an account or server-side profile.

The family guide explicitly explains that the current widget counts travellers
aged 12 and above, with a maximum of nine. It does not represent complete infant
or child booking functionality and does not promise adjacent seats.

## SEO and internal links

Metadata reuses `createPageMetadata` and the configured production origin
`https://easyfarebooking.com`. Every canonical page has a unique branded title,
description, canonical, Open Graph and Twitter metadata. Social images use the
existing `/newlogo.png`. BreadcrumbList JSON-LD uses real visible page labels;
serialization reuses the existing escaping utility. No fare, availability,
review or rating schema is generated.

The sitemap includes the directory, all nine canonical categories, all 23 route
guides and all existing destination guides, with duplicate URLs removed. Demo
search URLs remain excluded and retain their existing noindex metadata.

Deal guides link to existing destination guides when available. All 28 destination
pages now link to a geographically relevant planning category and up to three
relevant route guides. No new destination guides were invented for city pairs
whose cities are not already in the destination system.
